# ECS 首次接入

## 小白交付方式

- 用户直接给出服务器公网地址、root 账号和密码，就视为授权 AI 为当前任务登录该服务器；不要再要求 SSH 密钥、RAM 用户、GitHub、Coolify、VPN或用户自己执行命令。
- 用户也可以只打开已经登录的阿里云控制台并允许浏览器自动化。AI 自己识别普通 ECS 或轻量应用服务器，不能把轻量服务器的“防火墙”误称为普通 ECS“安全组”。
- 用户在对话中提供的密码可以用于本次登录。实际连接时通过 SSH 交互式密码提示或 Workbench 密码框输入；不得把密码放进命令参数、脚本、环境文件、Git、截图、日志或最终回复。

## 自动登录顺序

1. 先直接尝试公网 SSH。出现密码提示后使用用户提供的 root 密码，不要求用户重复输入。
2. 严格区分失败发生在哪一层：
   - `Permission denied` 或 Workbench 明确提示密码错误，才属于凭证校验失败。
   - `timeout`、`connection refused` 或一直没有密码提示，属于连接路径失败，不能说 root 或密码失效。
3. 公网 SSH 在密码校验前失败，而当前存在已登录的云控制台页面时，AI 自动选择目标实例并使用“远程连接 → Workbench 密码登录”。登录成功后直接继续任务，不要求 VPN，也不要求小白先修公网 SSH。
4. Workbench 终端不可操作时，普通 ECS 使用云助手，轻量应用服务器使用命令助手执行只读诊断；需要完整交互时再使用 Workbench 或救援登录。命令助手脚本按它实际使用的 shell 编写，不能假定 `/bin/sh` 支持 Bash 专属选项。
5. 只有公网 SSH、Workbench 和云端命令助手都不可用时，才停止并告诉用户一个最小控制台动作；必须给出准确产品页面和按钮，不让用户自行判断网络原理。

## 登录后流程

1. 先确认目标环境是公网 ECS 还是内网服务器，并确认业务系统、子模块、参与部门、本地项目和授权范围。
2. 按目标位置分类网络：中国 ECS、内网和本机直连；本流程不访问 GitHub 或 Coolify。
3. 先只读检查系统版本、磁盘、运行服务、项目目录、Git SHA、容器状态、反向代理和数据卷。
4. 修改源码必须回到 ECS 本地 Git 仓库提交；不要把运行容器内手改当正式版本。
5. 发布前备份数据库并确认精确目标。不得停止或重启无关服务。
6. 发布后核对健康检查、源码 SHA、运行镜像/容器、域名、日志和真实用户冒烟。
7. 完成后退出会话；不保存密码，不建立未经用户授权的长期 root 登录方式。

## 公网 ECS

- Alphabet 测试环境默认域名为 `{applicationSlug}.aifabei.staging.zhuojianai.com`。
- 同一 ECS 通过 Nginx 按 Host 路由多个项目；每个模块系统一个域名，不为子模块单独配置域名。
- DNS 必须先解析到目标 ECS；未解析时报告实际解析结果，不能用本机 hosts 冒充完成。
- 只公开 80/443；SSH 只允许管理来源。数据库、Redis、内部 API 不映射公网端口。
- HTTPS、`frame-ancestors`、健康检查和两个不同域名的并存验证全部通过后才算完成。

## 内网服务器

- 可以完成源码、容器和局域网访问验证。
- 灼见 SaaS 无法直接访问内网 IP 时，停止在“等待网络接入”状态，并列出需要的企业网关、VPN 或反向隧道条件。
- 未经明确授权不得自动建立穿透、开放路由器端口或修改企业防火墙。
