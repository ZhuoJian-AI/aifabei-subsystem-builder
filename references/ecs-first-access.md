# ECS 首次接入

## 两种身份不能混用

- **管理员首次初始化**：可以给服务器公网地址、root 账号密码，或提供已经登录的云控制台。管理员按 [SSH、VPN 与代理访问](ssh-access.md) 验证业务电脑实际会使用的连接路径；只有服务器端配置确实缺失时才使用 Workbench、云助手或轻量应用服务器命令助手修复。
- **业务负责人日常使用**：只给公网地址、root 账号和密码，并保持日常使用的 VPN 已启用。不得要求其提供阿里云账号、控制台、RAM、GitHub、Coolify、密钥对或自己执行命令；AI 应自行使用当前 Codex 已有的透明 VPN、本机代理或环境规定的网络路径。
- 用户在对话中提供的密码可以用于本次登录。实际连接时通过 SSH 交互式密码提示或 Workbench 密码框输入；不得把密码放进命令参数、脚本、环境文件、Git、截图、日志或最终回复。

## 自动登录顺序

1. 先遵守当前 Codex 的网络路由规则：用户、服务器档案或已知地域表明必须使用 VPN/代理时，首轮探测就走该路径，不先制造一次注定超时的直连。运行 `scripts/validate_ssh_access.py --host <公网地址> --ports 22,443 --json`，或用等价只读探测依次检查 SSH `22` 和已配置的 `443`。透明 VPN 不改变命令；当前环境只提供本机 HTTP 代理时，自动追加 `--proxy-url http://<本机地址>:<端口>`。选择第一个返回 SSH Banner 的端口，再启动带 PTY 的交互式 SSH；不要在 TCP 未连通时反复提交密码。
2. 严格区分失败发生在哪一层：
   - `Permission denied` 或 Workbench 明确提示密码错误，才属于凭证校验失败。
   - `timeout`、`connection refused` 或一直没有密码提示，属于连接路径失败，不能说 root 或密码失效。
3. 业务模式下 `22` 失败就自动尝试已配置的 `443`。`443` 返回 SSH Banner 后仍使用同一个 root 账号和密码；它不是新的账号、令牌或第二套登录方式。
4. 直连探测失败时，先使用当前 Codex 已有的 VPN/代理重试。透明 VPN 继续运行普通 SSH；HTTP CONNECT 代理运行 `scripts/ssh_via_http_proxy.py`，由脚本封装 OpenSSH `ProxyCommand` 和跨平台路径引号。代理地址可以来自当前环境规则或无凭证的本机代理设置，密码不得进入代理参数。
5. 直连和当前可用的 VPN/代理都在密码校验前失败时，停止并把状态归类为“当前 Codex 到服务器的网络未连通”。只需请负责人确认 VPN 已开启，不能说 root 或密码失效，也不得要求其登录云控制台。
6. 只有管理员模式才能在当前已有云控制台会话时改走 Workbench；普通 ECS 再用云助手、轻量应用服务器用命令助手修复服务器端监听或防火墙。命令助手脚本按它实际使用的 shell 编写，不能假定 `/bin/sh` 支持 Bash 专属选项。
7. 管理员从业务实际使用的外部 Codex 路径运行 Banner 探测，再用 root 密码完成一次真实 SSH 登录。标准 `22` 或已配置的 `443` 任一成功即可；需要 VPN 时在 Runtime 档案写入 `requiresVpn=true`。

## 登录后流程

1. 先确认目标环境是公网 ECS 还是内网服务器，并确认业务系统、子模块、参与部门、本地项目和授权范围。
2. 按目标位置分类网络：中国 ECS、内网和本机直连；本流程不访问 GitHub 或 Coolify。
3. 先只读检查系统版本、磁盘、运行服务、项目目录、Git SHA、容器状态、反向代理和数据卷。
4. 修改源码必须回到 ECS 本地 Git 仓库提交；不要把运行容器内手改当正式版本。
5. 发布前备份数据库并确认精确目标。不得停止或重启无关服务。
6. 发布后核对健康检查、源码 SHA、运行镜像/容器、域名、日志和真实用户冒烟。
7. 完成后退出会话；不保存密码，不建立未经用户授权的长期 root 登录方式。

## 公网 ECS

- Alphabet 测试环境默认域名为 `{applicationSlug}.aifabei.staging.zhuojianai.com`。
- 同一 ECS 通过 Nginx 按 Host 路由多个项目；每个模块系统一个域名，不为子模块单独配置域名。
- DNS 必须先解析到目标 ECS；未解析时报告实际解析结果，不能用本机 hosts 冒充完成。
- Web 只公开 80/443；管理入口可以使用 VPN 可达的 SSH `22`，也可以在确有需要时让 SSH `443` 与 HTTPS 复用。数据库、Redis、内部 API 不映射公网端口。
- HTTPS、`frame-ancestors`、健康检查和两个不同域名的并存验证全部通过后才算完成。

## 内网服务器

- 可以完成源码、容器和局域网访问验证。
- 灼见 SaaS 无法直接访问内网 IP 时，停止在“等待网络接入”状态，并列出需要的企业网关、VPN 或反向隧道条件。
- 未经明确授权不得自动建立穿透、开放路由器端口或修改企业防火墙。
